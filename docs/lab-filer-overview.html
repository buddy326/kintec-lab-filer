Lab Filer

How the nightly CAD file tidy-up is built and organised · November 2026

What it is

A set of Windows PowerShell scripts that run on CAD4 every night at 2am and keep the four CAD folders tidy: Scans, Models, Mill Jobs and NC Programs. It moves files that are in the wrong folder, archives finished work into the existing archive, clears out junk, and leaves a short PDF report each morning saying what it did and what needs a person.

It uses only what's already on CAD4: Windows PowerShell 5.1, Task Scheduler and Microsoft Edge. Nothing needs installing.

What happens each night

The tool looks at the files sitting directly inside each of the four folders. It never goes into subfolders such as Cropper Originals, Ben - Dev, USB Drive, Lincoln or Obama, and never touches anything outside the four folders. Each file gets exactly one of five outcomes:

OutcomeWhenWhat happens
LeaveIn the right folder and recentNothing
MoveIn the wrong folderMoved to its home folder, e.g. a .stl in Models goes to Scans
ArchiveIn the right folder, more than 14 days oldMoved to the archive: <Year>\<Folder>\<MM Mon>\
RemoveJunk: .zip anywhere, block-map .pdf in NC ProgramsMoved to a Holding folder, and deleted for good after 7 days
ReviewThe tool isn't sureLeft exactly where it is, and listed in the report for a person to sort out

Nothing is archived from NC Programs. FreeFileSync's own files (sync.ffs_db and similar) are never touched.

Things that go on the review list

  • A file type with no rule, e.g. .nc.
  • A file due for archiving whose archive month folder doesn't exist yet. The tool never creates archive folders; it only uses the ones that are already there.
  • A file whose name is already taken where it's going. Nothing is ever overwritten.
  • A loose .pim in NC Programs.

Safety

  • Nothing is overwritten, ever. A name clash means the file stays put and is listed for review.
  • Every action is written down as it happens, in a journal file, one per night.
  • Any night can be undone from its journal: every move goes back to where it came from.
  • Removed files aren't deleted straight away. They wait 7 days in Holding, in a folder named after the day they were removed.
  • Dry run first. The tool can show what it would do without changing anything. The first real run on CAD4 only happens after a dry run has been checked together.
  • Wrong settings stop it. If a configured folder doesn't exist (e.g. a typo in a path), it refuses to run instead of putting files somewhere new.
  • A failed file doesn't stop the night. If one file can't be moved (e.g. it's open in Orthomodel), it's marked as failed, the rest carry on, and it's tried again the next night.

The morning report

After each night's run, a short PDF named like File tidy-up 2026-12-03 0200.pdf goes into a Today's Report folder. The previous report moves to Archived Reports, filed by month, so Today's Report only ever holds the latest one. The report has:

  • a status line: "Nothing needs your attention" or "3 item(s) need your attention";
  • counts of each outcome;
  • sections for Could not be done, Needs a person to look at, Moved, Archived, Removed and Deleted from Holding, with errors in plain English.

If the newest run is more than a day old (CAD4 was off, for example), the report says last night's run may not have happened. The report can be emailed instead, if Kintec's email setup allows it.

How it's organised

Folders on CAD4

LabFiler\                      (location to be agreed, e.g. C:\LabFiler)
├── kintec-lab-filer\          the scripts and the settings file
├── Holding\2026-12-03\        removed files, waiting 7 days
└── Journal\2026\12 Dec\       one record per night, e.g.
        2026-12-03_020004 run.csv        what was done to each file
        2026-12-03_020004 nightly.log    everything the run printed

Reports\                       (location to be agreed, readable from Ben's PC)
├── Today's Report\            the latest PDF only
└── Archived Reports\2026\12 Dec\   earlier PDFs

The archive is the existing Archive 2022-Current on CAD4's D: drive. The 2012–2021 archive is never touched.

The scripts

ScriptWhat it does
Invoke-LabFiler.ps1The filer. On its own it's a dry run; with -Apply it makes the changes.
New-MorningReport.ps1Turns the latest journal into the PDF report, using Edge to make the PDF.
Undo-LabFilerRun.ps1Reverses one night, given its run ID (e.g. 2026-12-03_020004).
Start-LabFilerNightly.ps1What the 2am task runs: the filer, then the report, with a log.
Install-LabFilerTask.ps1Run once to create the 2am task in Task Scheduler (under Kintec → Lab Filer).
LabFiler.Common.ps1Small shared helpers used by the others.
New-TestData.ps1Builds a fake copy of the lab folders, for testing only.

Settings live in one file

Every rule is in config.json, not in the code: the folder locations, which file type belongs where, what counts as junk, the 14-day archive age, and the 7-day Holding time. Changing a rule means editing that file and doing a dry run, not changing the scripts.

The nightly task

  • Runs every day at 2:00 AM, whether or not anyone is logged in to CAD4.
  • Wakes CAD4 from sleep. If CAD4 was off at 2am, it runs as soon as it's back on.
  • Never runs twice at once, and stops itself if a run takes over 3 hours.
  • Runs under a normal Windows account with a stored password. It can't use the built-in SYSTEM account, because Edge won't make PDFs under it.
  • Task Scheduler's Last Run Result shows 0 for success and 1 for failure. The night's log ends with SUCCESS or FAILED and the reason.

How it was tested

Everything was built against a fake copy of the four folders, with made-up file names covering each rule and the awkward cases: files with one old date, trailing spaces, FreeFileSync files, protected subfolders, name clashes and locked files. No real lab files or patient data were used. Each test was checked against a written answer key.
